Pattern

Navigation and page structure

People always know where they are, how they got there and how to get back, on a phone or at a desk.

WCAG 2.2 AA

Overview

There are four shells, each with one navigation model:

  • News front page (the public landing, sections, stories, subscribe): the masthead (lockup, Sign in and Join free) with its section navigation (Latest, Events, Training, Nutrition, Faith & Body, Community, Pros), and the site footer with Newsletter, RSS, Send feedback, Privacy and Terms. Pages reached from it (Subscribe, the legal pages) use the plain masthead with a back link.
  • Public auth: the site header with Sign in and Join.
  • Member app: Home, Events, Services, Messages and Profile. A top bar from tablet up; a tab bar on phones; and the member footer under every page that scrolls (Send feedback, Preferences, Privacy, Terms). Messages fills the window and has none.
  • Admin console: a sidebar of ten sections grouped by the job (Publish, Gather, Community), with counts for what needs staff.

Inside a long page, side navigation lists its sections (Preferences, the legal pages). A choice between views of one thing is a segmented control; unsaved changes travel in a save bar, not in the navigation.

Every page starts with a skip link and has exactly one h1.

When to use

  • Primary navigation moves between top-level sections. Never more than five destinations in the tab bar.
  • Back link on a detail page returns to its list ("All events"); prefer it to a breadcrumb when the hierarchy is one level deep.
  • Tabs are links that filter one list (All, Published, Draft) and change the URL.
  • Chips filter in place; they are toggle buttons, not navigation.
  • Pagination for admin tables longer than one page.
  • Side navigation for in-page jumps on a long page with named sections: Preferences (Email, Notifications, Privacy, Suggestions, Your data) and the numbered contents of Privacy and Terms. Links to fragments; not more primary navigation.
  • Footers hold what everyone needs once in a while (feedback, preferences, legal), never a primary destination.

Structure

A page reads: shell navigation → back link (detail pages) → page head (title, subtitle, page action or search) → filters (tabs or chips) → content.

States

Navigation items have default, hover, focus, current (aria-current="page", styled by a bar and weight, never colour alone) and, for the tab bar, an unread dot on Messages. Chips use aria-pressed. The current section stays marked on its detail pages (Events is current on an event detail).

Responsive behaviour

  • Under 48rem the member top bar collapses to the brand and profile button, and the tab bar appears at the bottom; content gets bottom padding so nothing hides behind it.
  • Below 64rem the admin sidebar stacks above the content as a top strip and hides the group labels; from 64rem it is a sticky full-height column whose link list scrolls inside it when it outgrows the viewport.
  • The section navigation under the masthead scrolls sideways inside itself on phones.
  • Side navigation is hidden below 64rem (the sections simply follow one another); from 64rem it is a sticky column beside the content.
  • The member footer stacks on phones and pads its bottom by the tab bar's height; from 640px it is one row.
  • Tabs and chip bars scroll horizontally inside themselves rather than wrapping.
  • Breadcrumbs collapse to the parent link on phones.

Accessibility

  • Each navigation landmark has a distinct aria-label ("Main", "Admin", "Filter events", "Sections", "Preference sections", "Contents").
  • Footer links are 44px tall targets; side navigation links scroll to sections that set scroll-margin-top so the sticky header never covers the heading.
  • Console group labels are text inside the <nav>, not headings.
  • The skip link is first in tab order and jumps to #main.
  • Tab order follows reading order; Tab moves between items, Enter follows a link, Space toggles a chip.
  • Icon-only items (profile button) have an accessible name; tab bar items always show their text label.
  • Counts are read as part of the link name ("Services 3"); give them hidden context where the number alone is unclear.

Content

  • Section names are single nouns: Home, Events, Services, Messages, Profile.
  • Back links name the destination, not "Back": "All events", "Back to home".
  • Page titles match the navigation label they came from.
  • News sections are the story sections' names: Latest, Events, Training, Nutrition, Faith & Body, Community, Pros.
  • Console groups are one word for the job: Publish, Gather, Community.

Drift fixed during extraction:
