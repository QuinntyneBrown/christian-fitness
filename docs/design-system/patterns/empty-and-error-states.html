Pattern

Empty and error states

When there's nothing to show, or something broke, say why in one sentence and offer the one thing that helps.

WCAG 2.2 AA
  • Overview
  • When to use
  • Structure
  • States
  • Responsive
  • Accessibility
  • Content
  • Do and don't
  • Sources

Overview

Empty and error states replace content inside the page, never the whole shell: the header, tabs, filters and search stay so people can change course. Each has a title, one or two sentences, and one primary action.

  • First run: nothing exists yet ("No events yet"). Explain what will appear and how.
  • No results: filters or search hide everything ("Nothing here yet", "No members match “Jessica”"). Offer to clear them.
  • Load error: the request failed ("Events didn't load"). Offer Try again, and a way elsewhere.
  • Partial: some panels loaded, one failed; that panel shows an inline error, the rest stay.
  • System: 404, 403, 500 and offline get a full error page.

When to use

CauseComponentPrimary action
Nothing created yetEmpty stateCreate or browse ("New event", "Browse events")
Filter or search hides allEmpty state, tight"Show all events" / "Clear search"
Region failed to loadError state (.error-state)"Try again", plus a back link
One panel of many failedInline error"Try again" link
Page missing, forbidden, server down, offlineError pageHome, or Try again

Structure

Title (display face), text (muted, 1–2 sentences, max 60ch), actions. Errors add an icon and a reference code people can quote to the team.

States

A list region moves between loading, loaded, empty, no results and error. Keep filters visible in no-results and error so the person can change them. "Try again" returns the region to loading, not the whole page.

Responsive behaviour

The block is centred with a max width and stacks its actions on phones (full width below 30rem). Error pages keep the brand seal and shrink it on phones. Empty states inside cards (.empty-card) or lists (.empty-inline) use the tight size.

Accessibility

  • Error states are role="alert" so the failure is announced when it replaces the skeleton.
  • The title is a real heading at the right level for where it sits (h1 when it replaces the whole main content, as in Messages).
  • After "Clear search", focus returns to the search field; after "Try again", to the region.
  • Icons are decorative; the title carries the meaning.

Content

  • Empty: "No [things] yet." + what will make them appear + the action.
  • No results: "No [things] match “query”." + one suggestion.
  • Error: "[Thing] didn't load." + "We couldn't reach Christian Fitness." + reassurance about what's safe + what to do.
  • Never blame the person; never show raw codes or stack traces. The reference ("CF-E3K9") is for support only.

Drift fixed during extraction:

  • Admin load errors say "Try again in a moment" while member ones say "Check your connection and try again". Staff errors are more often server-side, so the difference may be intended; record it in content guidance or align.
  • Events no-results uses "Nothing here yet" (the prototype's copy) while admin no-results uses "No members match “Jessica”". Prefer the "No [things] match" formula.
  • Some error states offer a back link and some don't (admin errors have none).
