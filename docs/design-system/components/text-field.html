Component · Inputs

Text field

Text fields take one line of typing: a name, an e-mail, a password, a search, a six-digit code.

WCAG 2.2 AAStatus: stableNative <input>

Overview

Use a text field for short, free-form answers. Use a textarea for more than one line, a select or radio group when the answers are known. A text field always sits inside a form field with a visible label.

  • Text, e-mail, number, date, time use .input with the right type, autocomplete and inputmode.
  • Password uses type="password" with autocomplete="current-password" or new-password.
  • One-time code (.input--code) is large, centred and tabular for the admin two-step screen.
  • Search (.search) is a pill with a leading icon for filtering lists, labelled by aria-label or a hidden label.

Anatomy

  1. Label14px semibold, above the input, tied with for/id.
  2. Input16px text, 1px --color-border-strong border, --radius-md, padding --space-3 / --space-4.
  3. Hint or error14px, linked with aria-describedby; the error replaces the hint.

Sizes

One size: 16px text (so iOS does not zoom) and about 50px tall, above the 44px target. The code field uses 24px text. The search pill is 44px tall at 15px.

States

States are forced here with data-state; live inputs use :hover and :focus, plus the real disabled, readonly and aria-invalid attributes.

Both themes

Enter your name so people know who you are
  • Invalid: aria-invalid="true" turns the border danger and the hint becomes an error message; the message, not the colour, carries the meaning.
  • Read-only is used while a form submits (sign in, join): the values stay readable and selectable but cannot change.
  • Disabled is rare: prefer read-only, which stays in the tab order.

Responsive behaviour

  • Inputs fill their column at every width.
  • In two-column form layouts pairs stack below 640px.
  • The search pill is full width on phones and a fixed --layout-search-width from 640px.

Theming

Field colours come from component tokens on .field: --field-border, --field-border-focus, --field-border-invalid, --field-ring, --field-bg, --field-bg-readonly. In the dark theme the border lifts so it still meets 3:1 against the dark surface.

Accessibility

Role and pattern

Native <input> with a visible <label for>. Set type, autocomplete (WCAG 1.3.5) and inputmode. Placeholder is never the label.

Keyboard

KeyAction
Tab / Shift + TabMoves between fields.
EnterSubmits the enclosing form.
EscIn a search field, clears the query.

Focus

Focus turns the border accent and adds a 2px --color-accent-ring halo; the ring is visible against surface and canvas in both themes.

Labelling

Visible label via for/id; hint and error via aria-describedby; invalid via aria-invalid. Search uses a visually hidden label. Optional fields say "(optional)" in the label; required ones are the norm.

Motion

Border and ring transition over --duration-fast; reduced motion makes it instant.

Touch

About 50px tall; the label is also a tap target for the input.

Content

  • Labels are short nouns: "Email", "Full name", "Password".
  • Hints give the rule before people break it: "At least 8 characters".
  • Errors say how to fix it: "Enter your name so people know who you are", not "Invalid input".
  • Placeholders only show an example format, and only in search.
