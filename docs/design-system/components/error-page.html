Error page

When the app can't show what was asked for, an error page says so kindly and gives the way back.

WCAG 2.2 AAStatus: stable404 · 403 · 500 · offlineInside the app shell

Overview

Error pages replace the main content when a whole route fails. The header and tab bar stay, so the person is never stranded.

  • 404 Page not found: the route or record doesn't exist. "Go to home" and "Browse events".
  • 500 Something went wrong: the server failed. "Try again", "Go to home" and a reference code.
  • Offline: no connection and nothing cached for this route. "Try again"; queued messages and registrations are promised to send.
  • 403 Staff only: a member reached the admin console. A centred card names the signed-in account and the way to get access.

When a page's data fails but the route is fine, use the load error on the empty state. When the app is offline but has cached data, use the offline banner instead.

Anatomy

  1. Code.system__code, Barlow Condensed italic 8xl in the accent; decorative, aria-hidden.
  2. Title.system__title: the page heading, in plain words.
  3. TextWhat happened, that it isn't the person's fault, and what still works.
  4. ActionsOne primary way forward and one alternative.

Sizes

One size. The code is --font-size-8xl at every width; the block sits --space-12 below the header.

States

Each page is a single state. Shown here as rows by cause; the actions inside have button states. In the real pages the title is the page's h1; on this page it is an h2.

Responsive behaviour

Left-aligned in the page container at every width; actions wrap on phones. The 403 card is centred, full-width with 32px padding on phones and 40px from 640px.

Theming

The code reads --color-fg-accent, the text --color-fg-muted. In dark the accent brightens so the large code keeps 3:1. The 403 card uses --color-bg-surface on the canvas.

Accessibility

Role and pattern

A normal page: the title is the only h1, the code is hidden from assistive technology so it isn't read as "four hundred and four", and the reference is spoken in the text. On client-side navigation to an error route, focus moves to the h1. The server returns the matching HTTP status.

Content

  • Say what happened in plain words: "Page not found", "Something went wrong", "You're offline", "Staff only".
  • Take responsibility where it's ours: "That's on us, not you, and we've been notified."
  • Reassure about what's safe: "Everything else is right where you left it."
  • Give a reference code only for server errors.
