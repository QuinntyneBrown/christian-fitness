Inline message

Inline messages sit right where the problem or help is: under a field, or in place of one section that didn't load.

WCAG 2.2 AAStatus: stable.field__hint · .field__error · .inline-error

Overview

Three small messages that live inside the content rather than above it:

  • Field hint (.field__hint): help that prevents an error ("We'll send event reminders here. Never shared.").
  • Field error (.field__error): what is wrong with this field and how to fix it. It replaces the hint while shown.
  • Section error (.inline-error): one part of a page failed while the rest worked ("Messages didn't load. Your events are up to date.") with an in-place "Try again".

When the whole page fails use the error state block; when a whole form submit fails use an alert.

Anatomy

  1. Icon16px alert icon, aria-hidden.
  2. Title.inline-error__title: what didn't load.
  3. ReassuranceWhat still works.
  4. RetryA link-style button that reloads only this section.

Sizes

Field messages are 14px (--font-size-sm), 6px below the control. The section error is 14px with 16px padding and fills its section.

States

A field moves between three states: hint, error and valid (hint again). Errors appear on blur or submit, never on each keystroke, and clear as soon as the value is valid.

  • The section error's retry turns busy (spinner + "Loading…") while the section reloads, then the section returns or the error stays.
  • The error colour is never the only cue: the message text and the icon (section) say it.

Responsive behaviour

Messages wrap under their field at any width. The section error stacks icon and body in a row and the retry wraps under the text on phones.

Theming

Hint uses --color-fg-muted; field error and section error use --color-danger-fg, the section on --color-danger-bg. Both have dark values; no rule changes.

Accessibility

Role and pattern

Field messages are linked with aria-describedby; the invalid input sets aria-invalid="true". On submit, focus goes to the error summary, not to each message. A section error inserted after load uses role="alert" once; examples here omit it.

Keyboard

KeyAction
TabReaches the field, then the section's Try again.
EnterActivates Try again.

Focus

The input shows its focus ring; an invalid input keeps a danger border while focused. Try again shows the shared ring.

Labelling

The label names the field; the hint or error is its description. The error starts with the fix ("Enter…", "Use…").

Motion

No motion.

Touch

Try again is a text button padded to at least 24px height; on coarse pointers it extends to 44px.

Content

  • Errors say how to fix, not what's wrong: "Enter an email address, like name@example.com", not "Invalid email".
  • Hints are one sentence and explain why ("Never shared").
  • Section errors name the section and reassure about the rest: "Messages didn't load. Your events are up to date."
