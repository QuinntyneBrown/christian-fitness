Segmented control

A segmented control switches between two to four views of the same thing, in place: events by date or as series, a pick's art for each platform.

WCAG 2.2 AAStatus: new<nav> of links with aria-current

Overview

Use a segmented control when one list or one set of assets has a few views that each have their own address, and people flip between them: Events By date or Series; Community Pick art for Instagram, Facebook, WhatsApp or Slack. Each option is a link to its view, and the current one carries aria-current="page".

  • Default (.segmented): a surface pill with a hairline ring, 24px below the page head; the current option fills bordeaux.
  • Flush (.segmented--flush): no top margin, never wider than its container, and scrolls sideways when the options do not fit. With .segmented__option--ink the current option fills near-black instead, for the admin console.

Use tabs for more than four views or views with counts that change; filter chips to narrow a list, not to change how it is shown; a radio group or choice cards for an answer in a form.

Anatomy

  1. Track.segmented: --color-bg-surface pill with a hairline --color-border-default inset ring and 4px padding; as wide as its options.
  2. Current optionBordeaux fill (--color-accent) with the on-accent label; aria-current="page".
  3. Option.segmented__option: 14px semibold muted label, optional 16px leading icon, 8px × 20px padding, pill.

Sizes

One size: options about 37px tall inside a 45px track (8px padding plus 4px track padding), 14px labels. The track is as wide as its options; flush caps it at its container's width.

States

Current is the real aria-current="page" (or aria-selected="true" if the control is ever built as tabs). Hover and focus are forced here with data-state; live pages use :hover and :focus-visible. There is no disabled option: a view with nothing in it still opens and shows its empty state (events series-empty).

Responsive behaviour

  • Default: the track stays as wide as its two options at every width; at 360px "By date" and "Series (3)" fit with room to spare. Labels never wrap (white-space: nowrap).
  • Flush: max-width: 100% and overflow-x: auto, so on a phone the four platforms scroll sideways inside the pill instead of widening the page.
  • Under (pointer: coarse) options get an invisible hit-area pseudo-element, but sized to --target-min (24px), which the 37px option already exceeds.

Theming

Track --color-bg-surface with a --color-border-default ring; option label --color-fg-muted, hover --color-fg-default; current --color-accent/--color-fg-on-accent, or with --ink --color-bg-inverse/--color-fg-inverse (near-black in light, near-white in dark).

Accessibility

Role and pattern

A <nav> landmark with an aria-label ("View", "Platform") holding plain links; the current one has aria-current="page". Each view is its own URL, so this is navigation, not the APG Tabs pattern: no roving focus and no arrow keys. If a future screen switches panels without changing the URL, build it as APG Tabs (role="tablist", role="tab", aria-selected); the stylesheet already styles aria-selected="true".

Keyboard

KeyAction
Tab / Shift + TabMoves between options, in order.
EnterOpens that view.

Focus

The shared 2px --color-focus-ring at 2px offset around the focused option's pill. In the flush form the ring sits inside the 4px track padding, so the scrolling track does not clip it.

Labelling

The nav's aria-label names the choice; each link's text names the view, including the count ("Series (3)"). The repeat icon is decorative. The current view is announced from aria-current; on screen it is a filled pill against an unfilled track, a change of shape and luminance rather than of hue alone. In the dark theme the bordeaux fill is only about 2.2:1 against the dark track, so the label change (muted to on-accent) and aria-current carry the state; a lighter dark-theme accent fill would fix it.

Motion

Fill and label colour change over --duration-fast; the fill does not slide between options. Instant under reduced motion.

Touch

Options are about 37px tall, under the 44px rule. Their coarse-pointer extension uses --target-min (24px), so it adds nothing; proposed: --target-comfortable, as chips and small buttons use.

Content

  • One or two words per option, sentence case: "By date", "Series". Platform names as their owners write them: "WhatsApp".
  • A count goes in brackets after the label when it helps choose: "Series (3)".
  • Two to four options; the default view first.
