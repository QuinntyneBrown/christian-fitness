Dropzone

A dropzone is the empty place for an image: a dashed 16:9 frame that opens the file picker when pressed and takes a file dropped on it.

WCAG 2.2 AAStatus: newNative <button>Admin: story editor

Overview

Use a dropzone where an image belongs and none has been added yet, and the image is the first thing the page shows: the lead image at the top of a new story in the story editor. It is drawn at the image's own shape (16:9), so the writer sees the space the photo will fill. Once an image is added, the dropzone gives way to the photo with a Replace image button on it.

For an image inside a form among other fields (an event's image, a feedback screenshot), use the file field: a label, a Choose button, the file's name and a hint.

Anatomy

  1. Icon.dropzone__icon: the 28px (--space-7) image-plus icon, aria-hidden.
  2. Title.dropzone__title: semibold, the action: "Add a lead image".
  3. Hint.dropzone__hint: 14px, what fits: "16:9, at least 1600 px wide".
  4. FrameFull width, 16:9, --radius-lg, a 2px dashed --color-border-default border; content centred, 8px apart, in --color-fg-muted.

Sizes

One size: the full width of its column at 16:9, so its height follows its width (about 180px in a 320px column, 400px in the editor's 720px column). The icon is 28px.

States

Hover is forced here with data-state (live: :hover); focus with data-state (live: the shared :focus-visible ring); disabled is the real attribute. The stylesheet has no disabled, drag-over, uploading or invalid style for the block yet: a disabled dropzone looks like a default one, and a file dragged over it gets no feedback.

Lead image

Both themes

  • Disabled: while the story saves ("Saving…"), with the rest of the editor read-only. Because the block has no disabled style, it needs one (for example --opacity-disabled, as buttons use) before it ships.
  • Drag over: proposed .dropzone[data-state="dragover"] with the hover border and the accent colour, set while a file is over it.
  • Uploading and failed: not drawn in the mocks. Proposed: the frame keeps its place with a spinner and "Uploading…"; a rejected file shows a field error under it ("Use a JPEG, PNG or WebP image, 16:9") with aria-describedby.

Responsive behaviour

  • Full width of the editor's writing column at every width; the 16:9 ratio keeps its height in proportion.
  • The text is centred and wraps inside the frame; at 360px the title and hint each fit on one line.
  • On phones, where dragging files is rare, it is simply a large button that opens the picker (and the camera roll).

Theming

Border --color-border-default, hover --color-border-strong; content --color-fg-muted, hover --color-fg-default; no fill, so it shows the surface it sits on. Both follow the theme.

Accessibility

Role and pattern

A native <button type="button"> that opens the system file picker (a hidden file input behind it), so keyboard and touch users never need to drag (WCAG 2.5.7). Dropping a file is an extra for pointer users.

Keyboard

KeyAction
TabMoves focus to the dropzone.
Enter, SpaceOpens the file picker.

Focus

The shared 2px --color-focus-ring at 2px offset around the rounded frame.

Labelling

The button's text is its name, so it is read as "Add a lead image 16:9, at least 1600 px wide". Proposed: keep only the title in the name and link the hint with aria-describedby, so the name is the action alone. The icon is decorative.

Contrast

Title and hint
Title and hint, hover
Dashed border (non-text)
Dashed border, hover (non-text)
Focus ring on surface

Motion

Border and text colour change over --duration-fast; instant under reduced motion.

Touch

The whole frame is the target, the column's width and at least 180px tall.

Content

  • The title is the action, verb first: "Add a lead image".
  • The hint gives the shape and the minimum size: "16:9, at least 1600 px wide".
  • No "Drag and drop or click to upload": the frame and the button say it, and "click" assumes a mouse.
