Empty state

Empty states turn "nothing here" into the next step; the error block does the same when a page couldn't load.

WCAG 2.2 AAStatus: stable.empty-state · .empty-card · .empty-inline · .error-state

Overview

Every list and page in Christian Fitness has an empty and an error form:

  • First run (.empty-state): nothing exists yet ("No events yet", "No messages yet"). Explain what will appear and offer the way to make it appear.
  • No results: a filter or search matched nothing ("No members match “Jessica”"). Offer to clear or change it.
  • Empty card (.empty-card): one empty section on a busy page (home's next event).
  • Empty inline (.empty-inline): a small empty list inside a page section (landing's upcoming list).
  • Load error (.error-state): the page's data didn't load. Retry, a way elsewhere, and a reference for support.

For whole-app failures (404, 500, offline) use the error page; for one failed section among working ones, the section error.

Anatomy

  1. Icon (error only)40px circle in --color-danger-bg with the alert icon.
  2. Title.empty-state__title, display face, 3xl.
  3. Text.empty-state__text, muted, one or two sentences.
  4. Actions.empty-state__actions: one primary and at most one secondary.
  5. Reference (error only).error-state__ref, tabular, for support.

Sizes

Two spacings: the default .empty-state sits 64px below the page header for full-page emptiness; .empty-state--tight sits 16px below filters or tabs. The text is capped at --layout-form-max.

Reference CF-A2E5

  • Retry turns busy ("Trying again…") and the block is replaced by skeletons, then content or the error again.
  • A no-results state keeps the filters and search visible and filled in.

Responsive behaviour

  • The block is left-aligned with the page content at every width.
  • Actions wrap; on phones two buttons may stack.
  • .empty-card padding grows from 24px to 32px at 640px.

Theming

Titles use the default foreground, text --color-fg-muted; cards use --color-bg-surface with a hairline --color-border-default ring. The error icon uses the danger pair. All have dark values.

Accessibility

Role and pattern

Titles are real headings (h2 under the page h1), or a p when they restate a filter result. A load error replaces a busy region; in the app the error block uses role="alert" so the failure is announced once (omitted here). Reference codes are plain text that can be selected and copied.

Keyboard

KeyAction
TabMoves to the primary action, then the secondary.
EnterActivates the action.

Focus

Focus is not moved into an empty state on load. After a failed retry, focus returns to Try again.

Labelling

Action labels name the destination ("Browse events", "Show all events"); Try again carries a decorative icon only.

Content

  • First run: what will appear and how ("The team posts runs, workouts and gatherings every week. They'll show up here as soon as they're live.").
  • No results: repeat the query in curly quotes and suggest a fix ("Check the spelling, or search by email or home church instead.").
  • Load error: "Thing didn't load", then reassurance ("Your registration, if you have one, is safe.") and the reference.
  • Never blame the person; never say "No data".
