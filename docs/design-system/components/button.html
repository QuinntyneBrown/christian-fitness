Button

Buttons let people act: register, send, save, approve. One primary button per view tells them what matters most.

WCAG 2.2 AAStatus: stableNative <button>

Overview

Use a button when activating it changes something: it submits, registers, sends, opens a dialog or starts a process. Use a link when it only takes the person somewhere (a link may wear button styling, as "Register" on the landing page does, but stays an <a href>). Use a menu when one trigger offers several actions.

  • Primary (bordeaux) is the one action the view exists for: "Register", "Send request", "Sign in". Never two per view.
  • Secondary (outlined) is every other action that still matters: "Cancel", "Message", "Decline".
  • Ghost sits in dense chrome where an outline would be noise: "Sign in" in the public header.
  • Danger is for destructive actions and appears only inside a confirmation step.
  • Link looks like a link but behaves like a button: "Retry" inside a failed message.
  • Inverse and On brand are the primary and secondary pair for bordeaux panels (verse band, report card).
  • Icon button (.icon-button) is the round, label-less button for close, dismiss and back.

Anatomy

  1. Leading icon (optional)16px (--size-icon-sm), inherits the label colour, aria-hidden.
  2. LabelA verb phrase in sentence case, 15px semibold; it is the accessible name.
  3. ContainerPill (--radius-full), min-height from --control-height-*, 1px border in the button's border colour (transparent unless outlined).

Variants

Emphasis from highest to lowest; danger is reserved for destructive confirmations.

Inverse (white) is the panel's primary; on-brand (outlined white) its secondary. Both switch to the borealis focus ring.

Busy with spinner

Busy keeps the button in place, adds a spinner and a present-participle label, and ignores further presses.
HTML
<button class="btn btn--primary btn--lg" type="submit" aria-busy="true"><svg class="icon icon--spin" viewBox="0 0 24 24" aria-hidden="true"><path d="M21 12a9 9 0 1 1-6.219-8.56"/></svg>Signing in…</button><button class="btn btn--primary btn--md" type="submit" aria-busy="true"><svg class="icon icon--spin" viewBox="0 0 24 24" aria-hidden="true"><path d="M21 12a9 9 0 1 1-6.219-8.56"/></svg>Sending…</button>

Both themes

  • Busy sets aria-busy="true", shows the spinner icon and a "…ing" label ("Signing in…", "Sending…", "Saving…"). The rest of the form stays readable.
  • Disabled uses the native attribute at 70% opacity. Prefer an enabled button that explains the problem when pressed; disable only while a request is in flight or when the reason is visible ("Full").
  • Pressed toggles are chips with aria-pressed, not buttons.

Responsive behaviour

  • Auth forms use .btn--lg.btn--block at every width: the submit is the whole point of the screen.
  • Dialog and drawer footers put Cancel and the primary side by side with .btn--grow; on phones the dialog becomes a bottom sheet and the footer stays one row.
  • .btn-row--stack stacks buttons below --layout-breakpoint-sm (640px) and lays them in a row above it (empty states, profile hero).
  • Under (pointer: coarse) small buttons and icon buttons extend their hit area to 44 × 44px with an invisible pseudo-element, without changing their look.
  • Labels never truncate; a label that wraps at 360px is too long.

Theming

The button reads semantic tokens through six component tokens declared on .btn: --btn-bg, --btn-bg-hover, --btn-bg-active, --btn-fg, --btn-border, --btn-border-hover. Each variant only reassigns them, so a re-skin overrides component tokens and never touches the rules.

/* A partner event page with its own accent, without touching .btn */
.partner .btn--primary { --btn-bg: var(--color-highlight); --btn-fg: var(--color-fg-default); }

In the dark theme the accent brightens from bordeaux 700 to 600 (hover 500, active 400) so the white label stays above 4.5:1 while the button still reads as bordeaux; the outline uses the dark border tokens and the focus ring turns borealis.

Accessibility

Role and pattern

Native <button type="button">, or type="submit" inside a form (APG Button). A link styled as a button stays an <a href>; never a <div> with a click handler.

Keyboard

KeyAction
Tab / Shift + TabMoves focus to and from the button in DOM order.
Enter, SpaceActivates the button (Space on key up, so moving away cancels).
EscNo effect on the button; in a dialog it closes the dialog, not the busy request.

Focus

The shared ring, 2px --color-focus-ring at 2px offset, shows on :focus-visible only. On brand panels and in the dark theme it is borealis, which stays above 3:1 against bordeaux and the dark surfaces.

Labelling

The visible label is the accessible name. Icon buttons set aria-label with the verb ("Close", "Dismiss", "Back to conversations"). Busy buttons keep a visible label ("Signing in…") and set aria-busy; the form's live region announces the outcome.

Motion

Background, border and colour transition over --duration-fast (150ms). Reduced motion zeroes the duration in the tokens. The busy spinner stops rotating under reduced motion; the label still says what is happening.

Touch

Default (44px) and large (52px) buttons meet the 44px target. Small and extra-small (36px) extend to 44 × 44px on coarse pointers, and sit at least 8px (--space-2) apart in rows.

Content

  • Verb first, sentence case: "Register", "Send request", "Save changes", "Approve", "Create a profile". Never "OK", "Submit" or "Click here".
  • Name the object when context does not: "Save event" in the editor, "Save" in a row.
  • Busy labels use the present participle with an ellipsis character: "Saving…", "Sending…".
  • Destructive labels name what is lost: "Cancel registration", "Suspend Jordan", not "Confirm".
  • Keep it to three words where possible.
