Skeleton

Skeletons hold the shape of a page while it loads, so it settles into place instead of jumping.

WCAG 2.2 AAStatus: stableShimmer stops with reduced motion

Overview

Use skeletons for a first load whose layout is known: the home page, event lists, conversations, profiles, admin tables. Each skeleton matches the size of the content it stands in for (a date badge, a title line, an avatar), and known content (the greeting "Good morning, Grace", page titles) renders for real.

Use a spinner for a small refresh and a progress bar for a long, measurable task. If loading fails, the skeletons are replaced by an inline message or the error block on the empty state page.

Anatomy

  1. Shape.skeleton--date, --avatar, --button and so on: the exact box of the real part.
  2. Line.skeleton--text (title-height) with a width utility (.w-55) so lines vary.
  3. Short line.skeleton--text-sm for meta text; .skeleton-stack spaces lines 8px apart.

States

Skeletons have one state, loading, with a shimmer sweep. When data arrives the region swaps to real content in one step; partial results may replace sections one at a time.

{'na': 'A skeleton has no interactive or tonal states; the loading-to-content swap is described below.'}

Both themes

Loading events

Loading events

  • Show skeletons immediately; don't delay them like a spinner.
  • Keep the count close to reality (3 to 5 rows), never a screen of 20.
  • Under reduced motion the shimmer stops and the shapes stay as flat blocks.

Responsive behaviour

Skeletons live inside the real layout classes (.event-row, .event-grid, .split), so they reflow exactly as the content will. The banner image skeleton changes from 16:9 to 21:8 at 640px like the image.

Theming

The base is --color-bg-skeleton and the shimmer is a gradient to --color-skeleton-shine; both have light and dark values, so no theme-specific rule exists.

Accessibility

Role and pattern

The loading region sets aria-busy="true" and contains a .visually-hidden label ("Loading events"); in the app it is also aria-live="polite" so the arrival of content is not announced line by line. Skeleton spans have no content and no role; as decorative placeholders they are exempt from contrast minimums, so no pair is listed.

Keyboard

KeyAction
TabSkips skeletons entirely; known controls (search, filters) stay usable while lists load.

Focus

{'na': 'Skeletons are not focusable.'}

Labelling

One hidden label per region, naming what is loading. A page whose heading is not yet known keeps a visually hidden h1 ("Loading event").

Contrast

Motion

The shimmer sweeps continuously; prefers-reduced-motion removes the animation.

Touch

{'na': 'Not interactive.'}

Content

  • Render known text for real: the page title, greeting and filter chips.
  • The hidden label is "Loading" plus the thing: "Loading events", "Loading your home page".
